The menu

QuickTS adds one tile to the quick settings panel. Clicking it brings the tailnet up or down — or starts a login, if the daemon is waiting for one. Expanding it opens everything else.

Two icons appear in the panel itself: the QuickTS icon while the tailnet is up, and a second VPN icon while traffic is leaving through an exit node.

Only one submenu can be open at a time — that is a GNOME constraint, not a choice — so Exit node and Devices swap their own contents rather than opening a nested menu. Each offers a way back, and closing the menu returns both to their list.

Features

Exit nodes

Pick one, clear it, or take the daemon’s suggestion. Mullvad’s nodes are grouped by country rather than listed as several thousand rows.

Ping without a terminal

The daemon pings for us, so the answer includes whether the path is direct or going through a relay — usually the real question.

Taildrop, both ways

Send files to any eligible peer, and save the ones that arrive. The file chooser is the desktop portal, drawn outside the Shell.

Health you can act on

The daemon’s warnings, collapsed out of the way. A warning that carries a link becomes clickable; a permission failure offers the command that fixes it.

Honest state

The toggle follows the backend, not just the preference, so it cannot sit there reading “on” against a daemon that is waiting to be logged in.

Routing

Offer this machine as an exit node from the menu, and advertise subnet routes from the preferences window.

Multiple accounts

Switch between Tailscale profiles. The active one is read from the daemon rather than inferred.

A menu that fits

The menu is sized from the monitor’s work area, so a large tailnet scrolls inside it instead of running off the bottom of the screen.

Install

You must be the tailscale operator. Without it the daemon answers 403 to everything, and QuickTS can only tell you so:

sudo tailscale set --operator=$USER

From a release:

curl -LO https://github.com/napalm255/quickts/releases/latest/download/quickts@napalm255.github.io.shell-extension.zip
gnome-extensions install --force quickts@napalm255.github.io.shell-extension.zip
gnome-extensions enable quickts@napalm255.github.io

From a clone:

just setup
just install
just enable

A newly installed extension is only picked up when the Shell next starts. On Wayland that means logging out and back in — the Shell cannot be restarted in place.

Preferences

Setting Default Effect
Show offline devices on List peers that are not currently reachable.
Show Mullvad exit nodes on A tailnet with Mullvad enabled gains several thousand exit nodes; turning this off hides them all.
Maximum height 0 An upper bound in logical pixels, up to 2000. Zero uses whatever room the work area leaves below the menu, which is almost always what you want.
Advertised subnets none Subnets this machine offers to route for, as comma-separated CIDR prefixes.
Open the menu unbound A shortcut that opens quick settings with QuickTS expanded. Unbound by default so it cannot collide with an accelerator GNOME already claims.

Advertised subnets is not a stored setting. It reads and writes AdvertiseRoutes on the daemon directly. A settings key mirroring it would be a second source of truth, and would drift the first time anyone ran tailscale set.

Architecture

Four files import anything from gi:// or resource:///. Everything else imports nothing, and so runs under Vitest on plain Node with no GNOME in the loop.

File Imports Holds
extension.js the Extension base class, gettext The cancellation token and the wiring, in that teardown order. No logic.
prefs.js Adw, Gdk, Gio, GObject, Gtk Widget construction, in its own process — and a direct line to the daemon for the routes field.
modules/panel.js Gio, GObject, Pango, Meta, Shell, St, the Shell’s own modules The actor tree and the keybinding.
modules/io.js Gio, GLib, Soup — and nothing from the Shell The transport, the clock, the portal and file writing. Because it needs no Shell, it runs against the real daemon under plain gjs — and the preferences process can use it too.

The bus is a signal, not a source

The rule modules/bus.js exists to enforce: the IPN bus says that something changed, and /status and /prefs say what. No value is ever read out of a notification.

A peer as the bus describes it and a peer as /status describes it are different shapes, and keeping two translations of one dataset in agreement is not a thing that can be done. The module offers no way to get a peer out of a notification, and a test asserts its export list to keep it that way. While the menu is closed the re-read omits the peer map entirely, which is most of the payload on a large tailnet.

Cancellation settles the awaiter

One token per enable. Cancelling it aborts every request in flight, settles every pending wait, and drops every GLib source — and the last two happen in the same callback, deliberately. A timer removed without its awaiter being settled leaves a promise that never resolves, and an await that never returns keeps its whole call stack alive for the rest of the session.

The model is not a GObject

It is a plain observable: subscribe() returns its own disposer, and subscribers receive a whole consistent snapshot plus a list of what moved. There are no properties to bind and no notify:: ordering to get wrong, and the entire store is testable with no stubs at all.

One shape for a peer, one place for a decision

modules/peers.js is the only file that reads a raw peer field. Whether a node is the exit node comes from the preferences, not from the peer’s own flag, so the tick follows the click rather than lagging the network. A node shared in from another tailnet keeps enough of its name to stay distinguishable — the rows are clickable, so that is a correctness problem rather than a cosmetic one.

The same split runs throughout: pure modules decide, and modules/panel.js chooses the wording. That is why modules/health.js returns a kind and a value rather than a sentence — it keeps whole strings in front of a translator instead of fragments, and keeps the decisions loadable from a test.

The LocalAPI

QuickTS speaks to tailscaled over its Unix socket, trying /run/tailscale/tailscaled.sock and then /var/run/…. It is the same interface the tailscale command uses, and grants no privilege you did not already have.

Endpoint Used for
GET /status Peers, backend state, health warnings, the login URL. With ?peers=false while the menu is closed.
GET, PATCH /prefs Every switch, the exit node, and the advertised routes. A PATCH answers with the resulting preferences, so a change never waits on the bus.
GET /watch-ipn-bus The change signal, subscribed with the initial-state and rate-limit bits so the daemon answers at once and coalesces its own bursts.
GET /profiles/, /profiles/current, POST /profiles/{id} The account list, which one is in use, and switching.
GET /file-targets, PUT /file-put/… Sending. Files are streamed rather than read into memory.
GET /files/, GET, DELETE /files/{name} Receiving. The file is written before it is deleted from the daemon.
POST /ping A disco ping, which reports the route as well as the latency.
GET /suggest-exit-node The exit node the daemon would pick.
POST /login-interactive Signing in. The URL that comes back opens in a browser, once, and only when asked for. There is no logout here on purpose — see below.

Signing out is deliberately absent. A login is what unblocks the menu — without one the daemon has no identity and nothing here does anything. A logout is the opposite: an administrative action that invalidates the node key and needs another browser round trip to undo. A row with that consequence does not belong two clicks from the volume slider, and quick settings offer nowhere sensible to confirm it. tailscale logout is the right place for it.

Development

just              # list every recipe
just test         # unit suite
just lint         # eslint, prettier, gschema, shellcheck
just ci           # what CI runs: lint, test, security, build
just test-live    # headless Shell, bundle and live-daemon checks
just docs         # serve this page

Three layers of testing

just test runs the unit suite on plain Node. GNOME imports resolve to hand-written stubs through Vitest’s module aliases, not vi.mock. There is deliberately no gi://Soup alias — the day one is needed is the day a decision has leaked into the transport.

just localapi-check runs modules/io.js under plain gjs against the real daemon, with no compositor. A stub of libsoup can only prove the stub behaves; this is the only thing that notices Tailscale changing its JSON.

just test-live adds a headless gnome-shell and asserts that enable, disable and enable again leave no JavaScript error, no orphaned source and no object lifetime warning. The bundle check alongside it confirms every shipped icon actually decodes — that one exists because an icon once did not, and an icon that fails to load is completely silent.

Fixtures are written from the observed schema rather than captured. A real response carries node keys, addresses, the tailnet name and an account email, and this repository is public.

Packaging

just build makes the zip with plain zip, because gnome-extensions ships inside the gnome-shell package and CI has no GNOME. The cost of hand-rolling the archive is that nothing checks its layout, so scripts/pack-check.sh keeps the official tool as the authority and diffs the two listings. The uuid is written down once, in metadata.json; the justfile, the release workflow and the pack check all read it from there.

Releasing

Set the version in metadata.json and package.json, commit, tag and push. The release workflow checks the tag against both files before building anything: a tag that disagreed would otherwise publish a release called v0.2.0 containing a zip that tells GNOME it is 0.1.0, and nothing downstream would notice. 

git tag v0.2.0
git push origin v0.2.0
