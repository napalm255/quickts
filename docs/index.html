The menu

QuickTS adds one tile to the quick settings panel. Clicking it brings the tailnet up or down; expanding it opens everything else.

Section What it does
Warnings Whatever the daemon reports in its health list, plus a login prompt when it is waiting for one, and an explanation when it cannot be reached at all.
Exit node Every peer advertising itself as an exit node, with Mullvad's grouped by country. Selecting the one in use clears it.
Devices Every peer. Activating one copies its Tailscale address; a long press copies its full MagicDNS name instead.
Send files Taildrop. Peers that cannot receive are listed greyed out with the daemon's own reason, rather than omitted.
Settings Accept routes, accept DNS, allow LAN access, block incoming, Tailscale SSH.
Profiles Switch between Tailscale accounts. Hidden when there is only one.

Install

QuickTS needs GNOME Shell 50 and a running Tailscale daemon.

It also needs you to be the tailscale operator. Without that the daemon answers 403 to every request, and QuickTS says so in the menu and offers to copy the command that fixes it: 

sudo tailscale set --operator=$USER

From a release:

curl -LO https://github.com/napalm255/quickts/releases/latest/download/quickts@napalm255.github.io.shell-extension.zip
gnome-extensions install --force quickts@napalm255.github.io.shell-extension.zip
gnome-extensions enable quickts@napalm255.github.io

From a clone:

just setup
just install
just enable

A newly installed extension is picked up when the Shell next starts. On Wayland that means logging out and back in; the Shell cannot be restarted in place.

Preferences

Setting Default Effect
Show offline devices on List peers that are not currently reachable.
Show Mullvad exit nodes on A tailnet with Mullvad enabled gains several thousand exit nodes; turning this off hides them all.
Maximum height 0 An upper bound in logical pixels. Zero uses whatever room the monitor's work area leaves below the menu, which is almost always what you want.
Open the menu unbound A shortcut that opens quick settings with QuickTS expanded. Unbound by default so it cannot collide with an accelerator GNOME already claims.

Architecture

Four files import anything from gi:// or resource:///. Everything else imports nothing, and so runs under Vitest on plain Node with no GNOME in the loop.

File Imports Holds
extension.js the Extension base class The cancellation token, and the wiring. No logic.
prefs.js Adw, Gdk, Gio, Gtk Widget construction, in its own process. Its rules live in modules/shortcuts.js.
modules/panel.js St, Clutter, Meta, Shell, the Shell's own modules The actor tree and the keybinding.
modules/io.js Gio, GLib, Soup — and nothing from the Shell The transport, the clock and the portal. Because it needs no Shell, it can be run against the real daemon under plain gjs.

The bus is a signal, not a source

The rule modules/bus.js exists to enforce: the IPN bus says that something changed, and /status and /prefs say what. No value is ever read out of a notification.

That is not fastidiousness. A peer as the bus describes it and a peer as /status describes it are different shapes, and keeping two translations of one dataset in agreement is not a thing that can be done. The module offers no way to get a peer out of a notification, and a test asserts its export list to keep it that way.

The cost is a re-read per burst of changes, over a Unix socket. While the menu is closed that read omits the peer map entirely, which is most of the payload on a large tailnet.

Cancellation

One token per enable. Cancelling it aborts every request in flight, settles every pending wait, and drops every GLib source — and those last two happen in the same callback, deliberately. A timer removed without its awaiter being settled leaves a promise that never resolves, and an await that never returns keeps its whole call stack alive for the rest of the session.

The model is not a GObject

It is a plain observable: subscribe() returns its own disposer, and subscribers receive a whole consistent snapshot plus a list of what moved. There are no properties to bind and no notify:: ordering to get wrong, and the entire store is testable with no stubs at all.

The LocalAPI

QuickTS speaks to tailscaled over its Unix socket, the same interface the tailscale command uses. It grants no privilege you did not already have.

Endpoint Used for
GET /status Peers, backend state, health warnings, the login URL. With ?peers=false when the menu is closed.
GET, PATCH /prefs Every switch, and the exit node. A PATCH answers with the resulting preferences, so a change never waits on the bus.
GET /profiles/, /profiles/current The account list, and which one is in use.
GET /watch-ipn-bus The change signal, subscribed with the initial-state and rate-limit bits.
GET /file-targets, PUT /file-put Taildrop. Files are streamed, never buffered.
POST /login-interactive, /logout Signing in and out.

Testing

Three layers, each catching what the others cannot.

just test runs the unit suite on plain Node. GNOME imports resolve to hand-written stubs through Vitest's module aliases, not vi.mock. Two absences in that list are deliberate: the Clutter stub offers no ClickAction, because Clutter 18 has none, and there is no gi://Soup alias at all — the day one is needed is the day a decision has leaked into the transport.

just localapi-check runs modules/io.js under plain gjs against the real daemon, with no compositor. A stub of libsoup can only prove the stub behaves; this is the only thing that notices Tailscale changing its JSON.

just test-live adds a headless gnome-shell and asserts that enable, disable and enable again leave no JavaScript error, no orphaned source and no object lifetime warning. It also checks that every shipped icon decodes, which exists because one did not — an icon that fails to load is completely silent.

Fixtures are written from the observed schema rather than captured. A real response carries node keys, addresses, the tailnet name and an account email, and this repository is public.

Packaging

just build makes the zip with plain zip, because gnome-extensions ships inside the gnome-shell package and CI has no GNOME. The cost of hand-rolling the archive is that nothing checks its layout, so scripts/pack-check.sh keeps the official tool as the authority and diffs the two listings.

The uuid is written down once, in metadata.json. The justfile, the release workflow and the pack check all read it from there.

Releasing

Set the version in metadata.json and package.json, commit, tag and push. The release workflow checks the tag against both files before building anything: a tag that disagrees would otherwise publish a release called v0.2.0 containing a zip that tells GNOME it is 0.1.0, and nothing downstream would notice. 

git tag v0.2.0
git push origin v0.2.0
